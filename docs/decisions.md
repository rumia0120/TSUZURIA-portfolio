## データモデル

| テーブル | 役割 |
| --- | --- |
| `profiles` | 利用者の表示名を管理する。 |
| `diary_groups` | グループ名と現在の担当者を保持する。 |
| `group_members` | グループ内での執筆順、参加日時、退出日時を記録する。 |
| `diary_entries` | 本文、執筆者、作成日時、共有日時を保持する。共有日時の有無を下書きと共有済みの判定に使う。 |
| `diary_reactions` | 日記に対するメンバーの反応を保持する。1人が日記1件に付けられる反応は1つ。 |

執筆順と現在の担当を分けると、参加・退出でメンバーが変わっても、残った人の順番を使って次の担当を決められる。参加・退出の時刻は、共有済みの日記を誰に返せるかの判定にも使う。 [DBの初期定義](../supabase/migrations/20261112122409_diary_prototype.sql)

## 認証と日記の閲覧

Next.js の画面から、Supabase Auth のセッションを使ってデータを取得する。一覧と本文はいずれも DB の行レベルセキュリティ（RLS）で閲覧範囲を制限する。

| 日記の状態 | 閲覧できる人 |
| --- | --- |
| 下書き | 現在もグループに所属している作成者。 |
| 共有済み | 作成者が在籍していて、その日記の共有時点に参加済みだった現在のメンバー。執筆の順番にかかわらず閲覧できる。 |
| 作成者が退出した日記 | グループ内での閲覧を停止する。作成者が同じアカウントで再参加しても、以前の所属で書いた日記は再共有されない。 |

途中参加者に見せるのは参加時点以降に共有された日記に限る。書いた時点で想定していた読者の範囲を守るため。本文の URL を直接開いた場合も、同じ条件を適用する。 [取得処理](../app/diary-reader.tsx) · [閲覧・退出のルール](../supabase/migrations/20261115123724_diary_group_exit.sql)

## 招待と受け渡し

- グループの招待担当者が1人につき1本の招待リンクを発行する。リンクは7日間有効で、参加に成功すると使い切る。DB は招待コードのハッシュを保持し、期限、使用状況、重複参加、定員を確認する。
- 作成者を含めて3人そろうと、作成者から参加順に書く。現在の担当者だけが下書きを共有できる。共有日時の確定と次の担当への交代を DB の同じ処理で行い、操作が重なっても同じ下書きの受け渡しが重複しないようにする。
- 退出するとグループへの閲覧権限が止まる。担当者が退出した場合は残ったメンバーの順番で担当を決める。3人未満では受け渡しを保留し、再び3人そろうと再開できる。
- 招待担当者が退出した場合は、順番が先頭の在籍メンバーに招待権限を移し、未使用の招待リンクを無効にする。

[招待の実装](../supabase/migrations/20261115022558_diary_group_invites.sql) · [受け渡しと退出の実装](../supabase/migrations/20261115123724_diary_group_exit.sql)

## リアクションとメール通知

返信を書く余裕がないときも反応できるよう、いいね、にっこり、応援の3種類を用意する。同じボタンで取り消し、別のボタンで変更できる。画面では紙のノートを参考にした罫線と配色を使う。 [リアクションの実装](../app/diary-reactions.tsx)

メール通知の実装は `feature/turn-email-notifications` にある。通知は初期設定でオフ。オンにした利用者に番が回った場合は、日記の共有と担当交代を確定する処理で送信予定を記録し、別の処理で配信する。通知には「あなたの番です」とアプリへのリンクを載せる。送信前に番と通知設定を確認し、一度オフにしてからオンに戻したときに、以前の送信予定が復活しないようにしている。

## 開発時に確認したこと

| 項目 | 確認内容 |
| --- | --- |
| 招待と参加 | テストアカウントで招待から参加し、重複参加を拒否することと、3人そろうまで受け渡しを待つことを確認した。 |
| 閲覧と受け渡し | A → B → C → A と一周し、共有済みの日記を次の担当者が開けることを確認した。別グループのアカウントが本文URLを開くケースでは閲覧が拒否された。 |
| リアクションと退出 | 共有済みの日記への反応、退出者とその投稿が見えなくなること、2人になった場合の受け渡し停止を確認した。 |
| 新規登録の案内 | 登録送信後に確認メールの案内とログインへの導線を表示する。新規・登録済みのアドレスで同じ案内を表示する動作を模擬テストで確認した。 |
| メール通知 | 配信処理の模擬テストで送信内容、再試行、重複防止を確認した。実受信は未確認。 |

招待された新規アカウントが確認メールを経て参加する一連の操作は、上記の通しテストに含まれていない。退出は日記の閲覧を止める。保存期間と完全削除の設計は [ロードマップ](roadmap.md) に記載する。
