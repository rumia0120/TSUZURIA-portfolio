# TSUZURIA の開発ロードマップ

友だち3〜5人で日記を回す体験を、ダミーデータで確認できる Web アプリとして開発中です。対象とする使い方は [企画](concept.md)、閲覧権限などの実装方針は [設計判断](decisions.md) にあります。

## 実装状況

| 機能 | 状況 |
| --- | --- |
| アカウント・ログイン | `main` に実装済み。通常のログイン画面と招待リンクから新規登録に進める。 |
| グループ・招待 | `main` に実装済み。1回限りの招待リンクで参加し、3〜5人で日記を回せる。 |
| 日記の閲覧・下書き・受け渡し | `main` に実装済み。下書きと共有済みを分け、日記を渡す処理で次の担当者に進む。 |
| 退出・リアクション | `main` に実装済み。退出で閲覧・共有範囲が変わり、3人未満で受け渡しを一時停止する。閲覧できる共有済みの日記にはリアクションを付けられる。 |
| 番が回ったときのメール通知 | `feature/turn-email-notifications` に実装済み。通知は初期設定でオフ。宛先への実配信は未確認。 |

既存のテストアカウント3件を使い、招待から参加し、日記を一周させ、リアクションを付けて退出するまでを画面で確認しました。別グループのアカウントで本文を開けないことも確認済みです。ローカルで試す手順は [README](../README.md) を参照してください。

## 限定テストまでに確認すること

1. 招待された人が新規登録し、確認メールを経て参加できるかを、スマートフォンでも確認する。
2. 本文と下書きの閲覧、重複した受け渡し、別グループからのアクセス、退出と再参加を、ダミーデータで再確認する。データベースの回帰テストは `supabase test db` で実行できる。
3. メール通知を含める場合は、同意済みのテスト用アドレスで受信と停止の動作を確認する。通知が届かない場合も日記を渡せることを確かめる。
4. 日記とアカウントの保持・削除手順、試験の期間、参加者への説明と同意、問い合わせ方法を決める。

## 限定テスト後に判断すること

受け渡しが続いた回数と止まった理由、安心して書けたか、通知やリアクションが負担にならなかったかを振り返ります。観察結果と権限・データ管理の確認を踏まえ、今後の改善とアプリを公開する範囲を決めます。
